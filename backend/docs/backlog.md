# 백로그

작업 중 발견했지만 그 작업의 범위를 넘어 미룬 항목을 모은다. 각 항목은 **왜 그때 하지
않았는지**를 함께 적는다 — 범위를 지키려고 미룬 것인지, 조건이 안 갖춰져 미룬 것인지가
나중에 우선순위를 정할 때 중요하다.

## 보안

### presign 유효시간 축소 (조회용 GET 1시간 → 60초)

- **배경**: 리다이렉트(`/api/v1/images/{id}/file`·`/thumbnail`)에서는 발급된 presigned URL이
  즉시 소비되므로 1시간이나 유효할 이유가 없다. 짧을수록 유출 시 노출 창이 줄어든다.
- **왜 미뤘나**: 조회용 GET presign 1시간은 목록·상세(5-1·5-2)가 함께 쓰는 **기존 공용
  설정**이다. 리다이렉트만 다른 값을 쓰려면 용도별로 설정을 나눠야 하고, 그건 이번
  작업(엔드포인트 추가)의 범위를 넘는다.
- **하려면**: 리다이렉트 전용 TTL을 분리해 60초로 두고, JSON 응답 경로(5-1·5-2)는 1시간을
  유지한다. 앱이 JSON의 URL을 받아 곧바로 쓰지 않고 잠시 들고 있을 수 있어서다.
- 발견: 2026-08-05, 이미지 리다이렉트 엔드포인트 작업

### 미소유 리소스 접근 시도 로깅 (404-숨김 정책의 관측)

- **배경**: 이 프로젝트는 미소유·미존재를 구분하지 않고 404로 숨긴다(리소스 열거 방지).
  방어로는 옳지만, 그 대신 **공격 시도가 로그에도 안 남는다**. imageId를 순회하는 스캔이
  들어와도 정상 404와 구분되지 않는다.
- **왜 미뤘나**: 404-숨김은 이미지 리다이렉트만의 정책이 아니라 유사 이미지·문서화·카테고리
  썸네일 등 **여러 지점의 공통 관심사**다. 한 엔드포인트에만 로깅을 심으면 관측이 불균등해지고
  나중에 횡단 구현으로 바꿀 때 중복이 된다.
- **하려면**: 공통 예외 처리부(`GlobalExceptionHandler`)에서 "리소스는 존재하나 요청자 소유가
  아님"을 구분할 수 있는 신호를 받아 WARN 한 줄을 남기는 방식이 자연스럽다. 응답은 그대로
  404를 유지해야 한다(로그만 남기고 클라이언트에는 알리지 않는다).
- 발견: 2026-08-05, 이미지 리다이렉트 엔드포인트 작업
